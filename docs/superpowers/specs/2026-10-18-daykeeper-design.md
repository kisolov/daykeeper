# daykeeper — дизайн

Дата: 2026-10-18. Рабочее название: `daykeeper`.

## Зачем

Личный планировщик дня с pomodoro для Arch + Hyprland + Waybar. Пользователь
хочет одно место, которое знает, что он делает в конкретный день, напоминает
об этом, ведёт таймер и копит статистику — и которым он управляет в основном
голосом/текстом через Claude Code, а не формами.

Готовые решения (Super Productivity, TickTick, Flowkeeper, focusd) не подошли:
нужна связка «план дня + разные виды задач + pomodoro + привычки/цели/трекеры +
управление через ИИ + Telegram», живущая локально в его окружении.

Успех: утром открыл окно из waybar — видит свой день по порядку; работает по
таймеру; вечером «завершить день» — видит, что сделал; говорит Claude
«спланируй завтра» — и Claude планирует, учитывая статистику и цели.

## Роли частей (решение пользователя)

- **Программа — хранилище и исполнитель.** Держит всё: задачи по дням, цели,
  привычки, трекеры, историю и статистику. Показывает экраны, ведёт таймеры,
  шлёт напоминания. От Obsidian **не зависит** и туда ничего не пишет.
- **Claude Code — основной руль.** Задачи пользователь диктует Claude; Claude
  через MCP-сервер программы создаёт/правит/переставляет задачи, планирует
  следующий день, читает статистику и цели.
- **Окно (waybar / терминал) — в основном исполнение:** отметить, запустить
  таймер, переставить, завершить день, посмотреть дашборд.
- **Telegram-бот — пульт вне ноутбука,** работает, пока ноутбук включён.

## Цели / не-цели / анти-цели

Цели:
- один упорядоченный список дня из задач трёх видов;
- pomodoro 47/13 с автоматическим делением длинных задач;
- напоминания по времени (рабочий стол + Telegram);
- «завершить день» → сводка;
- дашборд: сегодня, фокус за неделю, цели, привычки, трекеры, мотивация;
- полный MCP-доступ для Claude Code;
- Telegram: напоминания, отметить, запустить таймер.

Не-цели:
- синхронизация между устройствами, облако, мобильное приложение;
- многопользовательность;
- планирование через Telegram, дашборд в Telegram;
- работа при выключенном ноутбуке;
- интеграция с Obsidian, календарями, Jira/GitHub.

Анти-цели (провал, даже если «работает»):
- список, разбитый на группы по видам задач (пользователь прямо отверг —
  «некрасиво»); вид задачи различается только значком/подписью в строке;
- мотивация в виде случайных цитат — только факты из его же статистики;
- окно, которое требует заполнять формы, чтобы спланировать день (основной
  путь — через Claude).

## Задачи

### Три вида (решение пользователя)

1. **Галочка** — без времени и таймера: сделал / не сделал (утренняя рутина,
   почистить зубы, зарядка).
2. **По времени** — привязана к интервалу (`09:00–10:00`). В начало интервала —
   напоминание; таймер пользователь запускает сам (кнопкой или из напоминания).
3. **На длительность** — длительность без привязки ко времени («поработать
   1 час», «тренировка 2ч»). Запускается когда удобно.

Задачу вида 2 и 3 можно отметить сделанной и без таймера.

### Порядок (решение пользователя)

Один список, порядок задаёт пользователь (и Claude). Любую задачу можно
двигать. Единственное ограничение: **задача с более поздним временем не может
стоять выше задачи с более ранним.** Свободные задачи (виды 1 и 3) стоят между
задачами со временем как угодно.

- Перемещение, нарушающее правило, отклоняется.
- *Моё решение:* если у задачи изменили время и правило нарушилось — она сама
  встаёт на ближайшую допустимую позицию.
- *Моё решение:* новая задача со временем без явной позиции встаёт в самую
  раннюю допустимую позицию после последней задачи с временем ≤ её; новая
  свободная задача без позиции — в конец.

### Pomodoro

Цикл **47 минут работы + 13 минут отдыха** (решение пользователя). Если задача
длиннее одного цикла — делится автоматически.

*Моё решение по счёту:* длительность — это «время на часах», включая отдых.
47+13 = 60, поэтому каждый час = один помидор: 1ч → 47+13, 2ч → 47+13+47+13.
Остаток короче часа: работа = min(остаток, 47), отдых = остаток − работа
(90м → 47+13+30). Для задачи «по времени» длительность = её интервал.
В макетах встречалось «1ч · 2🍅» — это ошибка макета, верно «1ч · 1🍅».

Таймер: пауза, пропустить фазу, стоп. Завершённые рабочие фазы пишутся в
историю с привязкой к задаче (это источник «минут фокуса»). Задача, у которой
отработаны все рабочие фазы, автоматически отмечается сделанной (*моё
решение*). Одновременно идёт не больше одного таймера.

Длительности 47/13 — в конфиге (*моё решение*), по умолчанию 47/13.

### Повторяющиеся задачи и привычки

*Моё решение:* привычка — это правило «галочка X по дням недели Y»; программа
каждый день сама кладёт такие задачи в список дня (в конец, если Claude не
расставил иначе). Отметка задачи-привычки = отметка привычки. Невыполненные
задачи на следующий день **не переносятся автоматически** — сводка их
показывает, а Claude при планировании предлагает перенести.

## Экраны (TUI)

Стиль — тема Lumon пользователя (`~/.config/waybar/style.css`: accent
`#6fb8e3`, accent-bright `#f2fcff`, muted `#4A6B80`, фон тёмно-синий),
моноширинный, первая буква акцентом — как в его модулях waybar.

### «Сегодня» (главный)

Макет утверждён (v2): заголовок с датой и счётчиком «выполнено/всего · минут
фокуса»; один список строк `[ ]`/`[x]`/`[▶]`, время слева у задач по времени,
справа `✓` у галочек или `⏱ 2ч · 2🍅`. Когда идёт таймер — над списком блок:
название задачи, «помидор N из M · работа/отдых», крупное оставшееся время,
прогресс-бар, «дальше: …». Внизу подсказки клавиш.

Действия: отметить/снять, запустить таймер, пауза/пропуск/стоп, переставить
(J/K), быстро добавить одну задачу (*моё решение*: минимальный ввод на
случай без Claude), «завершить день», перейти в дашборд, выйти. Конкретные
клавиши — на усмотрение строителя.

### «Завершить день» → сводка (решение пользователя: вызывается вручную)

Ничего не всплывает само. Сводка (*мои предложения, пользователь не
возражал*): сделано / не сделано, помидоров и минут фокуса, состояние привычек
и серий, прогресс целей за день, строка мотивации из фактов. После этого день
закрыт (отметки задним числом — через Claude, *моё решение*). План на завтра в
сводке не составляется — это делает Claude по просьбе пользователя.

### Дашборд (макет утверждён: «всё ок»)

Блоки: **сегодня** (прогресс, фокус, следующая задача); **фокус за неделю**
по дням + сравнение с прошлой; **цели** с числом и сроком и отставанием от
темпа; **привычки** — сетка за 14 дней и серия 🔥; **трекеры** — числа раз в
день (сон, вес, настроение) со спарклайном за 7 дней; **строка мотивации** —
факт из статистики («лучшая неделя по фокусу за месяц», «зарядка 10 дней
подряд, рекорд 14»). Навигация по неделям, история.

## Цели и трекеры

- **Трекер** — именованный числовой показатель, одно значение в день
  (вес, сон в часах, настроение 1–5). Вносится через Claude или Telegram.
- **Цель** — число + срок + источник прогресса. Источники (*моё решение*):
  минуты фокуса по задачам с меткой/проектом (например «catalogue-bot 20ч в
  неделю»), значение трекера («вес 75 кг к декабрю»), счётчик отмеченных задач
  с меткой («30 уроков английского»). «Отставание от темпа» — линейный темп к
  сроку или к концу периода.
- Задачам можно назначать метку/проект (*моё решение*) — по ней цели и считают.

## Напоминания

- В начало интервала задачи «по времени»: уведомление на рабочий стол
  (`notify-send`) и в Telegram, с действием «запустить таймер».
- Конец рабочей фазы и конец отдыха — уведомление на рабочий стол и в Telegram
  (*моё решение*).
- *Моё решение:* без «пилящих» повторов; одно уведомление на событие.

## Telegram (решение пользователя: три функции)

Только: (1) получать напоминания; (2) отмечать сделанное; (3) запускать
таймер. Кнопки inline: «▶ запустить», «✓ сделано»; команда, показывающая
список дня кнопками. Бот принимает команды **только из чата пользователя**
(chat id в конфиге); токен — в конфиге/переменной окружения, не в репозитории.
Long polling, без вебхуков (ноутбук без белого IP).

## Waybar

Модуль `custom/daykeeper` (заменяет текущий `custom/pomodoro` от focusd,
который после запуска daykeeper убирается из конфига; сам пакет `focusd`
пользователь может удалить). Показывает в стиле его модулей: идёт таймер —
`focus 31:12` / `brk 09:40`; нет таймера — следующая задача по времени или
счётчик дня (на усмотрение строителя, коротко). Классы CSS для состояний
(work/break/paused/idle). Клик — открыть окно через
`~/.local/bin/waybar-float.sh` (как остальные модули) с правилом окна в
`~/.config/hypr/waybar.lua`; правый клик — пауза/продолжить. Модуль читает
состояние быстро (без поднятия тяжёлого процесса раз в секунду).

## MCP для Claude Code

MCP-сервер (stdio), регистрируется в Claude Code пользователя. Покрывает всё,
что нужно, чтобы Claude полностью вёл планирование: чтение дня (любой даты),
создание/правка/удаление/перестановка задач (с тем же правилом порядка и
понятной ошибкой при нарушении), отметки, управление таймером, привычки, цели,
трекеры (включая внесение значений), статистика и сводки за день/неделю/период,
история. Набор и имена инструментов — на усмотрение строителя; ответы — в
форме, удобной модели (компактный текст/JSON с датами в локальном времени).

## Как это сделано (моё решение, пользователь отдал выбор мне)

- **Python 3** (как остальные его TUI-скрипты).
- **SQLite** — одна база в `~/.local/share/daykeeper/`. Конфиг —
  `~/.config/daykeeper/config.toml`.
- **Демон** под `systemd --user`: владеет таймером, расписанием напоминаний и
  Telegram-ботом; единственный, кто пишет состояние таймера. TUI, MCP и waybar —
  клиенты (через локальный сокет или общую базу — на усмотрение строителя),
  несколько окон показывают одно состояние.
- **TUI на Textual** в стиле выше.
- **CLI** `daykeeper` с подкомандами (открыть TUI, статус для waybar, базовые
  действия) — точка входа для waybar и `waybar-float.sh`.
- Часовой пояс — локальный системный; «день» — календарная дата (*моё
  решение*; работа после полуночи относится к новому дню).
- Проект: `~/projects/daykeeper`, git, тесты на логику (порядок, деление на
  помидоры, статистика, цели).
